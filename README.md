# ATMResolve AI — Consolidated local-first portfolio project

ATMResolve AI is a **synthetic, human-reviewed** ATM complaint-investigation copilot. It combines a trained text classifier, retrieval-augmented generation (RAG), mock transaction tools, deterministic checks, a local LLM, and a LangGraph workflow.

> This is a portfolio prototype, not a banking system. Use synthetic records only. It never connects to real accounts or issues real refunds. The RBI note in `data/documents/` is a locally written summary with an official source link, not an RBI-authored document. Verify current policy wording from the source before relying on it.

## Consolidation

This folder combines your existing repository with the more implemented starter archive. See [MERGE_NOTES.md](MERGE_NOTES.md) for the merge decisions. The starter implementation replaces placeholder versions; existing evaluation/citation helpers and Streamlit pages are retained.

## Architecture

- **Scikit-learn**: TF-IDF + Logistic Regression trained on BANKING77; saves an actual test report.
- **SQLite**: synthetic transaction records, complaints, ATM events, approvals and audit events.
- **Chroma**: persistent vector search for policy and procedure documents.
- **LangChain**: document splitting, embeddings and retrieval.
- **Ollama**: local Qwen model for explanations and local `nomic-embed-text` for embeddings.
- **LangGraph**: investigation orchestration and human review interrupt with SQLite checkpoints.
- **FastAPI**: API layer; **Streamlit**: operator UI.

## Requirements

- Windows 10/11, Python 3.12, Git, Ollama.
- 16 GB RAM and CPU-only should be enough to start with `qwen3.5:2b`, though response generation may be slow.
- Internet is needed to install Python packages, download the dataset/models and access public source documents. Runtime inference is local.

## 1. Create the environment

Open PowerShell in this project folder:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

If PowerShell blocks virtual-environment activation, use `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` in that terminal, then activate again.

## 2. Start local models

Install Ollama from https://ollama.com/ and then run:

```powershell
ollama pull qwen3.5:2b
ollama pull nomic-embed-text
ollama run qwen3.5:2b
```

Ask the model to say `OK`, then exit the model prompt. Keep Ollama running in the background while using the app. If the 2B model is too slow, try a smaller available model and update `LLM_MODEL` in `.env`.

## 3. Download BANKING77 and train the ML classifier

Download the official Hugging Face dataset and export the official training/test split:

```powershell
python scripts/download_banking77.py
```

Train a reproducible TF-IDF + Logistic Regression baseline and evaluate on the official test split:

```powershell
python -m src.ml.train
```

For ad-hoc evaluation of a trained model against any compatible `text,label` test CSV, the retained helper is `src.ml.evaluate.evaluate_model`. The official split metrics generated by `python -m src.ml.train` are saved under `artifacts/ml/`.

This creates `artifacts/ml/intent_classifier.joblib`, `metrics.json`, `classification_report.json` and `confusion_matrix.csv`. Metrics are generated by the actual run; no values are hard-coded. BANKING77 is a general English banking-intent dataset, **not** an Indian ATM-dispute dataset. A separate set of synthetic Indian ATM examples is used for workflow testing, not presented as a validated clinical/financial dataset.

## 4. Initialize SQLite and synthetic records

```powershell
python -m src.storage.repository
```

This creates the local app database and idempotently seeds fictional transactions and ATM events. It does not use real customer information.

## 5. Build the local RAG index

The `data/documents/` folder includes a synthetic demo-bank manual and a locally written RBI guidance summary that links to the official source. The summary is not official RBI text; check the original source before changing policy logic.

```powershell
python -m src.rag.ingest
```

The command downloads no paid service and persists embeddings in local Chroma. It needs Ollama and the embedding model to be running. Add only documents you are permitted to use, with source attribution. Do not put private customer records into the knowledge base.

## 6. Run tests

```powershell
python -m pytest -q
python -m compileall -q api app src scripts tests
```

The bundled tests cover the pure rules, synthetic SQLite seed records, and helpful ML setup errors. After installing dependencies and preparing the local models, complete the full end-to-end demo checks described below.

## 7. Start the application

Open two PowerShell terminals, activate `.venv` in both, and use the project directory as the working directory.

Terminal 1 — API:

```powershell
uvicorn api.main:app --reload
```

Open http://127.0.0.1:8000/docs to inspect the API.

Terminal 2 — UI:

```powershell
streamlit run app/streamlit_app.py
```

Streamlit displays the case queue, investigation results, policy search and ML metrics. Submitting an investigation may take some time because local LLM inference runs on the CPU.

## Demo scenarios

The database seeds fictional cases `TXN-0001` through `TXN-0005`, including a pending reversal, a successful dispense, a completed reversal, a missing ATM log and conflicting events. Try a complaint against each reference and compare the evidence shown by the tool calls.

## Workflow overview

1. Validate complaint and create a case.
2. Classify intent and retain the model score.
3. Retrieve policy chunks from Chroma.
4. Fetch synthetic transaction/ATM events from SQLite.
5. Apply deterministic checks; do not let the LLM calculate entitlements.
6. Ask the local LLM to draft a structured recommendation with retrieved citations.
7. Persist state, pause for a human decision, and resume from the same case thread.
8. Save the review decision and audit event.

## Troubleshooting

- **Dataset download error**: confirm internet access, then rerun `python scripts/download_banking77.py`.
- **Model not found**: run `ollama pull qwen3.5:2b` and `ollama pull nomic-embed-text`.
- **Ollama unavailable**: open Ollama and check `http://localhost:11434` is reachable.
- **Classifier missing**: run the download and training steps first.
- **RAG index empty**: run `python -m src.rag.ingest` after Ollama is running.
- **Slow response**: close other memory-heavy programs, use one request at a time, and consider a smaller Ollama model.

## Free software vs hosted availability

Python packages, the local database/vector store and local inference are free to run. This does not guarantee free cloud hosting or a remote GPU. The simplest free demo is local execution plus a public GitHub repository and a short screen recording.
